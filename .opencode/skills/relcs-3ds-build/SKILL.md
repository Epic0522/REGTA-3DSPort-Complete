# reLCS 3DS build

This repo (`/home/max/lcs_3ds`) is NOT self-contained: the devkitARM SDK and
host packaging tools live outside `repo/`, at the workspace root.

## Required environment (every build/package command)

```sh
export DEVKITPRO=/home/max/lcs_3ds/sdk-r55
export DEVKITARM=$DEVKITPRO/devkitARM
export PATH="$DEVKITARM/bin:$DEVKITPRO/tools/bin:$PATH"
```

`common/devkitarm-r55.mk` hard-errors unless `arm-none-eabi-gcc` reports
exactly `10.2.0` AND `devkitARM release 55` — a generic ARM GCC 10.2 will not
work. Without the exports above, `scripts/build.sh` defaults `DEVKITPRO` to
`/opt/devkitpro`, which does not exist in this environment, and fails with a
confusing error from `devkitarm-r55.mk`, not a clear "compiler missing"
message.

## Full build

```sh
DEVKITPRO=/home/max/lcs_3ds/sdk-r55 DEVKITARM=/home/max/lcs_3ds/sdk-r55/devkitARM \
  /home/max/lcs_3ds/repo/scripts/build.sh relcs
```

Aliases accepted: `lcs`, `stories`. This runs
`make -C stories/build -f GNUmakefile LOADING_PIPELINE=1 BOTTOM_LOADING=1 BOTTOM_RADAR=1`.
Outputs: `stories/build/relcs.elf` (~58 MB), `relcs.3dsx` (~4 MB), `relcs.lst`,
`.map` (literally named `.map` — a makefile quirk, not a typo).

Clean build takes ~1 minute on a 20-core machine. It is never a true no-op:
`src/extras/GitSHA1.cpp` is regenerated by `printHash.sh` on every invocation,
which relinks the ELF/map/lst/3dsx even with no source changes.

## THE FLAG-CONSISTENCY TRAP

`stories/build/obj/` is a **flat** directory (not fingerprinted by flags like
III's `obj/$(FINGERPRINT)/`). Running a bare
`make -C stories/build -f GNUmakefile` without the same `LOADING_PIPELINE=1
BOTTOM_LOADING=1 BOTTOM_RADAR=1` flags reuses previously-compiled objects and
silently produces a mixed-flag binary. Always use `scripts/build.sh relcs` or
pass the identical flag set by hand. To force a clean rebuild:
`make -C stories/build -f GNUmakefile clean` (clean only the tree you're
rebuilding — do not touch III/miami's `build/` dirs unnecessarily).

## Single-file compile (fast iteration / syntax check)

```sh
make -C /home/max/lcs_3ds/repo/stories/build -f GNUmakefile \
  LOADING_PIPELINE=1 BOTTOM_LOADING=1 BOTTOM_RADAR=1 \
  obj/src/core/BottomScreen3DS.o
```

Add `-n` to preview the exact compiler invocation without running it. Force
recompilation of one file with `-W ../src/core/Foo.cpp`. Helper targets:
`make -C stories/build source-info` / `object-info`.

## Packaging a .cia

`repo/packaging/production_cia/build_production.sh` is a portable bash
script (table-driven over re3/revc/relcs). It now accepts an optional list of
games — you do NOT need all three ELFs built:

```sh
BANNERTOOL=/home/max/lcs_3ds/hosttools/bannertool \
MAKEROM=/home/max/lcs_3ds/hosttools/makerom \
THREEDSXTOOL=/home/max/lcs_3ds/sdk-r55/tools/bin/3dsxtool \
  /home/max/lcs_3ds/repo/packaging/production_cia/build_production.sh relcs
```

Omit the trailing `relcs` to package all three games (each requires its own
ELF to already be built). Output lands in
`repo/packaging/production_cia/output/` (gitignored):
`GTALCS For Nintendo 3DS.3dsx` and `.cia`, plus intermediate `.bnr`/`.smdh`.

Known-good relcs CIA sha256 (from the 3DS menu accept/cancel remap commit
`f1ae416`) for sanity-checking that packaging still works end-to-end:
`f852b41abf69d8a69c3e493f91dc863581d78f0a4a29cac71df555b545362122`. A
different hash after a source change is expected and correct; use this only
to confirm the packaging pipeline itself still runs and produces a similarly-
sized artifact, not as an exact-match regression test.

## Deploying to a real 3DS over the network (3dslink)

`$DEVKITPRO/tools/bin` does **not** ship `3dslink` (only `3dsxdump 3dsxtool
bin2s bmp2bin generate_compile_commands mkromfs3ds padbin picasso raw2c
smdhtool`). If `/home/max/lcs_3ds/hosttools/3dslink` doesn't already exist,
build it — it's a tiny host tool (zlib is its only dependency) with no
autotools output committed, so a plain autoreconf/configure won't work
out of the box:

```sh
git clone --depth 1 https://github.com/devkitPro/3dslink.git /tmp/opencode/3dslink
gcc -O2 -std=gnu99 -DPACKAGE_STRING='"3dslink 0.6.3"' \
  -o /home/max/lcs_3ds/hosttools/3dslink \
  /tmp/opencode/3dslink/host/src/main.c -lz
```

(`PACKAGE_STRING` is normally generated by `configure` from `configure.ac`'s
`AC_INIT` version; defining it by hand skips the whole autotools step.)

Usage — the 3DS must already be sitting in Homebrew Launcher (or another
netloader-capable app) waiting for a connection; it listens on TCP/UDP 17491:

```sh
/home/max/lcs_3ds/hosttools/3dslink -a <3DS-LAN-IP> stories/build/relcs.3dsx
```

Add `-s` to keep a server running after upload so the console's stdout/stderr
streams back to the terminal. **Do not wrap this in a short Bash timeout** —
a ~4 MB `.3dsx` over Wi-Fi takes noticeably longer than a quick command, and
killing the transfer mid-upload leaves the console in a bad state (it may
boot the partial app or drop out of listening mode), requiring the user to
relaunch Homebrew Launcher on-device before the next attempt.

## Verification after a build/packaging change

```sh
python3 -m unittest discover -s /home/max/lcs_3ds/repo/scripts/tests -p 'test_*.py'
/home/max/lcs_3ds/repo/scripts/verify-layout.sh
```

`test_3ds_world_and_menus.py`'s `test_compiled_menus` needs `DEVKITARM`
exported (see above) — it defaults to a `toolchains/devkitARM-r55` path that
does not exist in this environment.
